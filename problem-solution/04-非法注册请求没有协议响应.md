# 问题 04：非法注册请求没有协议响应

## 现象

用户名或密码为空时，客户端等待 5 秒后显示“请求超时”，而不是立即显示注册失败。

## 根因

服务端的 `createUser` 在参数校验失败后直接返回，没有向 socket 写入任何内容：

```text
客户端发送注册 JSON
        │
        ▼
服务端发现字段为空
        │
        └── 直接 return（协议响应丢失）
```

请求—响应协议的重要不变量是：服务端接受并解析了一条请求后，应明确返回一条结果。业务校验失败不是网络超时，两者不能用同一种现象表示。

## 修复

- 先构造统一的 `mysqlCreateUserFeedBack` 响应；
- 字段为空时跳过数据库写入，但仍把结果设为 `failed`；
- 正常写入和重复用户名错误继续走原有 MySQL 逻辑；
- 发送缓冲区仍由完成回调持有，保持原有异步架构。

## 验证

分别发送三类请求：

| 输入 | 预期响应 |
|---|---|
| 空用户名或空密码 | 立即返回 `failed` |
| 新用户名与非空密码 | 返回 `success` |
| 已存在的用户名 | 返回 `failed` |

三种情况都必须收到一行以换行符结尾的 JSON，不允许依赖客户端超时来判断业务失败。
