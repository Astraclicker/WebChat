# 问题 02：聊天窗口没有发送反馈和接收者输入

## 现象

用户登录后点击“发送”，窗口中看不到已发送的内容，也无法选择聊天对象。即使网络发送成功，界面也像是没有执行任何操作。

## 为什么不是 WSL

协议测试已经证明 WSL2 中的 TCP 链路可以完成注册和登录。真正的问题位于客户端 GUI 层：

1. 接收者被硬编码为 `root`，界面没有接收者输入框；
2. 消息输入框和发送按钮采用绝对坐标，控件存在重叠；
3. 发送后既不清空输入框，也不把内容写入聊天记录；
4. 收到的消息只显示为短暂提示，没有持久聊天记录。

服务端本来就支持通过 `receiver` 字段按用户名路由，因此不需要改变 TCP、JSON、Boost.Asio、Qt 或 MySQL 架构。

## 修复

- 用 Qt 布局组织聊天记录、接收者、消息输入框和发送按钮；
- 默认接收者仍为 `root`，兼容原先的测试方式，同时允许修改；
- 消息进入客户端发送队列后立即在本地聊天记录中回显；
- 服务端转发来的消息追加到持久聊天记录；
- 空接收者或空消息不发送，并显示明确错误。

## 验证方式

准备两个已经注册的用户，例如 `root` 和 `alice`：

1. 启动两个客户端，分别登录两个用户；
2. `alice` 的接收者填写 `root`，发送一条消息；
3. `alice` 应立即看到 `[我 -> root]` 记录；
4. `root` 应看到 `[alice]` 记录；
5. 交换接收者后反向发送，结果应对称。

如果发送方有本地记录而接收方没有，应从服务端登录状态和目标用户名继续排查，而不是归因于 WSL 图形环境。
