# 问题 03：跨线程消息队列竞争与界面忙等

## 现象

登录、注册或收消息可能表现为无反馈、延迟、界面假死，空闲时客户端也会持续占用较高 CPU。

## 根因

客户端存在两个事件循环：

```text
Asio 线程：socket 收包 -> requestedDeque.push_back(...)
                              │
                              │ 无同步并发访问
                              ▼
Qt GUI 线程：检查队列 -> front() -> pop_front()
```

`std::deque` 不支持一个线程写、另一个线程同时读。没有互斥量时属于 C++ 未定义行为，不保证“多数时候看起来能用”就正确。

GUI 线程还有两种忙等：

- 登录/注册槽函数用循环等待响应，期间 Qt 无法正常处理绘制和输入；
- `QTimer::singleShot(0, ...)` 不断递归轮询，队列为空时仍尽可能快地运行。

## 修复

1. 把接收队列改为 `chatClient` 私有状态；
2. Asio 写队列和 Qt 取队列都使用同一个互斥量；
3. 对 GUI 只暴露立即返回的 `try_pop_message`；
4. 使用 20 ms Qt 定时器处理消息，不阻塞 GUI；
5. 使用单次 5 秒定时器报告登录/注册超时，不创建嵌套事件循环；
6. 根据响应类型异步切换登录、注册和聊天窗口。

## 验证

- 客户端干净编译通过；
- 登录请求发出后窗口仍可重绘；
- 响应到达后能够正确切换窗口；
- 消息队列为空时客户端不再执行 0 ms 自递归；
- 连续发送多条消息时，每条 JSON 只会被取出一次。

进一步检查线程问题时，可以为纯网络层建立 ThreadSanitizer 构建；Qt 和系统库可能产生额外报告，因此要先确认报告栈是否指向项目自己的队列访问。
