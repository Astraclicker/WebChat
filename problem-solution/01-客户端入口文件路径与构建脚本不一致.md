# 问题 01：客户端入口文件路径与构建脚本不一致

## 现象

按照 README 在仓库根目录执行客户端配置命令：

```bash
cmake -S client -B client/build -G Ninja -DCMAKE_BUILD_TYPE=Release
```

CMake 在生成阶段失败，并报告：

```text
Cannot find source file: main.cpp
```

## 系统边界与定位思路

这个错误发生在“配置/生成”阶段，还没有进入 C++ 编译阶段。因此应先检查 `client/CMakeLists.txt` 声明的源文件，而不是检查编译器、Qt 或网络代码。

上一笔提交把入口文件从 `client/main.cpp` 移到了 `client/src/main.cpp`，但 `add_executable` 仍引用旧路径。CMake 的相对路径以当前 `CMakeLists.txt` 所在目录为基准，因此它会继续寻找已经不存在的 `client/main.cpp`。

## 修复

把客户端可执行目标的源文件改为 `src/main.cpp`，并在修改处说明路径变化的原因。没有改变目标名称、依赖关系或项目架构。

## 验证

使用全新的临时构建目录，排除旧缓存影响：

```bash
rm -rf /tmp/web_chat_test_client_build
cmake -S client -B /tmp/web_chat_test_client_build \
    -G Ninja \
    -DCMAKE_BUILD_TYPE=Release
```

成功信号是 CMake 输出 `Build files have been written to`。如果仍报告找不到源文件，应检查当前分支是否包含本次修复，以及命令是否在仓库根目录执行。
