# 问题 02：聊天消息没有形成可观察闭环

## 现象

登录后点击“发送”，窗口看不到任何反馈。单独启动一个客户端时，这个现象稳定出现。

## 根因

问题不在 WSL，而在消息路由设计：

1. 客户端把接收者硬编码为 `root`；
2. 服务端只向“用户名等于接收者、并且不是发送者”的会话投递；
3. 因此非 `root` 用户需要另一个已登录的 `root` 客户端才能看到消息；
4. `root` 给 `root` 发消息时又会被“排除发送者”条件过滤；
5. 原界面没有聊天历史，只用短暂提示框显示收到的消息。

这意味着单客户端测试在任何操作系统上都不会形成“发送 → 服务端 → 接收”的闭环。

## 最小修复

本轮目标是让学习项目跑通，不扩展成完整聊天产品，因此：

- 保留接收者固定为 `root` 的原协议；
- 不增加联系人列表、接收者输入框或持久聊天记录；
- 服务端把消息投递给目标用户的同时，也回显给发送者；
- 客户端继续用原有提示框显示收到的消息。

判断条件从“目标用户且不是发送者”调整为“发送者或目标用户”。使用逻辑“或”可以避免发送者就是 `root` 时投递两次。

## 尚未解决的设计边界

- 不能在界面上选择接收者；
- 不保存聊天历史；
- 接收者离线时没有失败回执；
- 没有群聊、在线用户列表和消息持久化。

这些是后续学习阶段可以实现的功能，不是本轮“跑通”所必需的修复。

## 验证

1. 只启动一个客户端并登录任意用户；
2. 输入非空消息并点击发送；
3. 客户端应收到服务端回显，并弹出 `[用户名]: 消息`；
4. 再启动 `root` 客户端时，非 `root` 用户发送的消息应同时到达发送者和 `root`；
5. `root` 自己发送时只收到一份，不重复投递。
